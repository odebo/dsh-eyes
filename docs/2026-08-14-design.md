# ds-eyes — Design Spec

**Date:** 2026-08-14
**Status:** Draft (awaiting approval)
**Goal:** Give the text-only DeepSeek model `deepseek-v4-pro` automatic image understanding in the dsh Web UI dialog, without switching models. Pasted images are silently converted to text evidence by a separate vision model (`tongyi/qwen3.7-plus`) before the text model sees the message.

## Problem

The user runs dsh web with two mify models:
- `tongyi/deepseek-v4-pro` — text-only, the preferred agent model for task execution.
- `tongyi/qwen3.7-plus` — multimodal (declared `input: [text, image]`), verified working on mify's Anthropic path with 200×200 PNGs.

dsh's image admission gate (`packages/host/apiproxy/src/api-proxy.ts:2488`) rejects pasted images for any model whose `inputModalities` does not include `'image'`, **before** the request reaches the agent loop. So a text-only main model cannot receive pasted images, and `agent/pre-step` hooks (which run inside the loop, after the gate) never see the image. This is the architectural reason modlens registers a wrapper provider that declares image input.

The user does not want to switch models back and forth, and does not want to reuse modlens (it requires an unrelated `DEEPSEEK_API_KEY` and an external vision engine; it was uninstalled).

## Approach: wrapper provider (route A)

Register a **wrapper LLM adapter** under a new provider route `deepseek-eyes`. The wrapper:

1. Declares `inputModalities: ['text', 'image']` on the model it wraps → passes the admission gate.
2. In `stream()`, walks `options.messages`, finds every `image` content block, reads its bytes via the attachment service, sends each to `tongyi/qwen3.7-plus` (via mify's Anthropic path) to get a text description, and **replaces the image block with a `text` evidence block**.
3. Rewrites `options.provider` from `deepseek-eyes` → `mify-deepseek` and delegates the now-text-only request to `ctx.llm.stream()` (the real pi-ai adapter), which calls `deepseek-v4-pro` on mify.

The user selects `deepseek-eyes / deepseek-v4-pro` as their model. Pasting an image is admitted (wrapper declares image input), converted to text at request time, and answered by the same DeepSeek text model — no model switching, no `DEEPSEEK_API_KEY`, the durable session log keeps the native image block (the UI shows the thumbnail; only the wire messages carry evidence text, matching modlens's proven approach).

### Plugin entry (`lib/index.js`)

Function-plugin form (per packages/CLAUDE.md convention; avoids out-of-tree `@deepseek-ai/dsh-llm` resolution issues that bit modlens):

```js
export const name = 'ds-eyes'
export const inject = ['llm', 'credentials', 'attachments']  // all optional via ctx.get
export function apply(ctx, config) { ... }
```

`apply()`:
1. Reads config (vision provider/model/credential, upstream text provider/model).
2. Constructs a `DeepSeekEyesAdapter` (plain object duck-typed as `LlmAdapter`, supplying `providerInfo`, `providerRetryPolicy`, `listModels`, `resolveModel`, `stream` — the methods modlens v3.9.0 omitted, causing silent registration failure).
3. `ctx.llm.registerAdapter(['deepseek-eyes'], adapter)` — returns a disposer.
4. `ctx.llm.registerConfigurableProviders([{ provider: 'deepseek-eyes', displayName: 'DeepSeek Eyes', settingsNs, settingsPath: [] }])` so the route appears in the model selector / Models page.

### The wrapper adapter (`stream()`)

```
stream(options):
  signal = options.signal
  for each message in options.messages:
    for each content block:
      if block.type === 'image':
        bytes = await ctx.get('attachments').readImage(block.attachment, signal)  // StoredImageAttachment
        description = await describeWithVision(ctx, bytes, config.vision, signal)  // calls qwen3.7-plus
        replace block with { type: 'text', text: "[image] ${description}" }
  // rewrite route to the real text provider and delegate
  delegateOptions = { ...options, provider: config.upstream.provider, model: config.upstream.model }
  yield* ctx.llm.stream(delegateOptions)
```

`listModels('deepseek-eyes')` / `resolveModel(...)` return the wrapped model id with `inputModalities: ['text', 'image']` — this is the single fact the admission gate checks.

### Vision call (`describeWithVision`)

Calls `tongyi/qwen3.7-plus` via mify's **Anthropic** path (`POST https://api.llm.mioffice.cn/anthropic/v1/messages`), the same path dsh's pi-ai adapter uses and that we verified returns vision results. Sends the image as a base64 `source` block (`{type:'base64', media_type, data}`) plus a focus prompt. Resolves the API key from `ctx.get('credentials').resolve(config.vision.credential)`.

- Reuses the existing `MIFY_DEEPSEEK_API_KEY` credential (same key, different model on the same gateway). No new key.
- Per-attachment result caching (LRU Map on the adapter instance): the same image pasted across steps is described once; concurrent readers join the first promise; failed reads are evicted (matches modlens's proven caching).
- Focus prompt: a fixed "Describe this image in detail, in 简体中文" (config.overrides `vision.prompt` later if needed). Keeps v1 simple — free-text description, not structured JSON (per the user's earlier preference, deferred to a v2 mode switch).

### Config (settings namespace `ds-eyes`, applies: 'live')

```yaml
ds-eyes:
  upstream:
    provider: mify-deepseek        # the real text adapter to delegate to
    model: tongyi/deepseek-v4-pro  # the text model that answers
  vision:
    provider: mify-deepseek        # informational; the call is hardcoded to the anthropic path
    model: tongyi/qwen3.7-plus     # multimodal model for image description
    credential: MIFY_DEEPSEEK_API_KEY  # DSH credential ref
    baseURL: https://api.llm.mioffice.cn/anthropic
  language: zh
```

Defaults baked into the schema boundary so it works with zero user config (the values above are the verified-working ones). The user can override via Settings if they later add a different vision model.

## Data flow

```
user pastes image in dialog (model = deepseek-eyes/deepseek-v4-pro)
  → admission gate: resolveModelInfo('deepseek-eyes','deepseek-v4-pro').inputModalities = ['text','image'] → PASS
  → agent loop calls ctx.llm.stream({ provider:'deepseek-eyes', model:'deepseek-v4-pro', messages:[...image...] })
  → ds-eyes adapter.stream():
      - read image bytes via attachments.readImage
      - POST to mify /anthropic/v1/messages with qwen3.7-plus + base64 image → "a red square..."
      - replace image block with text block "[image] a red square..."
      - delegate: ctx.llm.stream({ provider:'mify-deepseek', model:'tongyi/deepseek-v4-pro', messages:[...text-only...] })
  → deepseek-v4-pro answers based on the text evidence
  → session log keeps the original image block (UI shows thumbnail); wire messages carried evidence text
```

## Error handling

- **Vision call fails** (network, 400, timeout): the image block is replaced with a text block `"[image: vision failed — <reason>]"` and the request still delegates to the text model. The user sees the failure inline, the turn is not lost. (Better than modlens, which aborts the whole request.)
- **No credential**: throw `MISSING_CREDENTIAL` at the first vision call (loud, with the same actionable message pattern as llm-deepseek: "store MIFY_DEEPSEEK_API_KEY through the credentials service").
- **Image too small / "image format illegal"** (the 2×2 failure we hit): caught as a vision-call failure → inline text, not a crash. Documented minimum in README (use real screenshots, not 1×1 pixels).
- **Signal aborted**: `readImage` and the vision fetch honor `options.signal`; mid-vision abort evicts the cache entry.
- **Adapter registration**: supply all base-class methods so registration never silently fails (the modlens v3.9.0 regression).

## Testing

- **Unit (vitest, keyless):** message-rewriting logic (image block → text block), cache hit/miss/eviction, config validation. Mock `ctx.llm.stream` and the vision fetch.
- **Integration (keyless, fake vision):** boot a minimal `ctx` with a stub attachment service + stub `ctx.llm.stream` that records delegated options; assert the wrapper rewrites provider to `mify-deepseek`, strips image blocks, and delegates text-only messages.
- **Real-API smoke (needs MIFY_DEEPSEEK_API_KEY, manual):** paste a real 200×200 image in the Web UI with model `deepseek-eyes/deepseek-v4-pro`; assert the turn returns a text answer referencing the image content. This is the acceptance test — the same `xiaomi/mimo-v2-omni`/`qwen3.7-plus` vision path already verified.

## Scope (v1) and non-goals

**v1 includes:** wrapper provider, single fixed vision model (qwen3.7-plus), free-text description, per-attachment caching, inline error handling, settings namespace, README.

**v1 non-goals (deferred):**
- Structured JSON output / coordinate grounding (vision-toolkit already covers pixel-level work; ds-eyes is for conversational "what's in this image").
- Multiple vision-model sources / failover chain (modlens's complexity we're avoiding).
- A `see_image` tool (the wrapper makes pasting automatic; a tool is redundant for the dialog-paste use case).
- Client/browser half (no Settings GUI page in v1; config via `settings.yaml`. A Settings tab is a later addition if the user wants it.)
